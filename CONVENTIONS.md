# Conventions

Conventions settle routine decisions so contributors can reuse them. As a rule of thumb, document a routine choice here after similar decisions have been made three times. State the choice and when it applies.

This personal reference organizes guidance into [Functionality](1-functionality.md#functionality), [Factoring](2-factoring.md#factoring), [Prose](3-prose.md#prose), and [Change records](4-history.md#change-records). Defaults describe the usual approach, and editorial preferences guide writing and final polish. Repository rules and explicit agreements take precedence. Policy references point to the proposed rules in [POLICIES.md](POLICIES.md#policy-outline), which apply where a project adopts them. [PRINCIPLES.md](PRINCIPLES.md) explains the rationale, and [WORKFLOWS.md](WORKFLOWS.md) provides command recipes.

Convention IDs name topics and stay stable when rules move or their wording changes. Links below convention groups identify the shared requirements or principles that support them. Entries are defaults unless marked as editorial preferences or identified as restatements of an outline requirement. Defaults allow judgment under [P.rules](modules/collaboration.md#p.rules).

Use the [topic index](README.md#topic-index) to locate conventions and their supporting policies.
